SUBTASK 1.1 COMPLETED - Implement debounced write logic in useXterm hook
================================================================================
Date: 2026-01-09
Status: ✅ COMPLETED
Commit: a6978c22

IMPLEMENTATION DETAILS:
-----------------------
Added requestAnimationFrame-based debouncing to useXterm.ts:

1. **New Refs:**
   - writeBufferRef: Accumulates incoming data chunks
   - rafIdRef: Tracks scheduled animation frame ID

2. **flushWriteBuffer() Function:**
   - Called once per animation frame (~60fps)
   - Writes accumulated buffer to xterm.write()
   - Clears buffer after flush
   - Resets RAF ID

3. **write() Function (Modified):**
   - Accumulates data in buffer instead of immediate write
   - Schedules RAF flush if not already scheduled
   - Ensures only one RAF is scheduled at a time

4. **writeln() Function (Enhanced):**
   - Flushes any pending buffered data first
   - Cancels pending RAF
   - Then performs immediate writeln() for critical messages

5. **dispose() Function (Enhanced):**
   - Cancels any pending RAF
   - Flushes remaining buffered data to prevent data loss
   - Ensures cleanup on component unmount

ACCEPTANCE CRITERIA MET:
------------------------
✅ Add a write buffer (ref) to accumulate incoming data chunks
✅ Use requestAnimationFrame to schedule a flush of buffered data
✅ Ensure only one animation frame is scheduled at a time
✅ Flush buffered data to xterm.write() on each animation frame
✅ Clear the buffer after flushing
✅ Add cleanup logic to flush any pending data on unmount
✅ Preserve existing write() and writeln() function signatures
✅ Ensure no data loss during batching
